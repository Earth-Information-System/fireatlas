    local-dev → conus-dps integration: use-case-driven merge plan

    Analysis date: 2026-06-24. Base: origin/conus-dps (tip 93031d0, tag 1.5.1). Integrate from local-dev (it contains checkpoints; staging is a superseded older snapshot).

    The work on local-dev isn’t really a flat list of features — it’s three capabilities, each a bundle of changes that only delivers value when merged together. Organizing by use case so partial merges don’t ship half a capability.

    Status legend: ✅ in conus-dps · 🟡 partially in (core landed, this piece missing) · ❌ missing

    Use case 1 — Run global FEDS (arbitrary region from a shapefile)

    The headline capability. Requires all of the following together; merging any subset leaves global runs broken.

    Component Where conus-dps status Notes
    Shapefile region input (--reg_shp overrides bbox) FireRunDaskCoordinator.py, FireMain.py, FireIO.get_reg_shp, algorithm_config.yaml, run_dps_cli.sh 🟡 partial — unusable conus-dps has docstring + some get_reg_shp plumbing but no --reg_shp argparse arg (only --regnm/--bbox/--tst/--ted). Can’t actually pass a shapefile. local-dev adds the CLI arg + Africa/SE_Asia geojson run path
    Local-timezone handling (approximate local time from region centroid; local-day preprocessing; ted = current timestep at centroid) FireTime.py (aprox_local_datetime, get_current_timestep), preprocess.py (preprocess_NRT_file) ❌ missing conus-dps FireTime.py has only a docstring mention. Commits: 99c5ff9, def1fe2, c534aaa, afb0abe, PR #198 local_day
    Multi-CRS / per-region projection (accept string CRS codes; ~12 regional projections; CRS validation; buffer in projection units) FireConsts.py (EPSG_CODE: int → int\|str, expanded allowed, check_epsg/is_projected), FireIO.py ❌ missing conus-dps still EPSG_CODE: int with only (3571, 32610, 9311, 6933). local-dev adds EPSG:3035 (EU), ESRI:102022 (Africa), EPSG:3576 (polar) etc. + CRS.from_user_input validation; static-source buffer 1000m → 0.01 projection units. Each global region needs its own projected CRS — global runs are broken without this
    fireIDs don’t reset over new year (intended universal — all runs incl. CONUS NRT) FireObj.py, FireIO.py ❌ missing (opposite behavior) conus-dps still has newyear_reset() + save_newyearfidmapping (it does reset). local-dev disables it: 912ec58 “Do not reset fire IDs when year changes”, 6e754a1 (Tess’s PR cherry-pick, “don’t reset fids but check length”), PRs #197/#216. Decision: apply to all runs — clean swap, no flag
    Region projection/CRS handling for shapefiles FireMain.py 🟡 likely partial 57e885c/fc0c839 region_proj_bug, CRS clarification
    Global land-cover (get_LCT_Global) retry + “Savanna” type FireFuncs.py, FireConsts.py ✅ core landed get_LCT_Global already in conus-dps; local-dev only adds LCT-fetch retry logic + spelling fix — minor refinement, optional
    Global FEDS manual-run notebook notebooks/16_Global_FEDS_Manual_Run.ipynb ❌ missing The runbook for this use case
    dt2t accepts all valid inputs FireTime.py, tests/test_firetime.py ✅ landed (PR #262) foundation already in

    Bottom line: this is the biggest real gap. Core date plumbing (dt2t) is in, but the shapefile CLI path, timezone logic, and fireID-rollover fix are all missing and interdependent — global FEDS needs the whole bundle.

    Use case 2 — Run FEDS locally in a sensible way (dev workflow)

    For running/iterating off-MAAP without the S3/DPS round-trip.

    Component Where conus-dps status Notes
    Local-run documentation docs/run_local.md ❌ missing the entry point for this use case
    READ_LOCATION local-vs-S3 branching FireConsts.py, preprocess.py, FireRun.py ✅ landed constant + branching present in conus-dps
    Unify Run + Run_local (single path keyed on READ_LOCATION) FireRunDaskCoordinator.py (~467-line net divergence) 🟡 partial / diverged 873f6ee “Merge Run and Run_local”; biggest manual-reconciliation file
    S3 read-location pollution fix FireRunDaskCoordinator.py 🟡 61a5a98 “specify s3 read location to fix override from run_config.yaml”
    VIIRS SP SFTP monthly download notebook notebooks/20_Download_VIIRS_SP_SFTP.ipynb ❌ missing needed to get input data locally
    Tests don’t persist outputs between runs tests/conftest.py, tests/... ❌ likely missing ce80bb8 cleanup

    Bottom line: the mechanism (READ_LOCATION) is in, but the docs, the SFTP download notebook, and the Run/Run_local unification are not — so the documented, repeatable local workflow doesn’t exist on conus-dps yet.

    Deep-dive: FireRunDaskCoordinator.py + preprocess.py are one entangled unit

    Full line-by-line read of both diffs (2026-06-24). This overturns the “do use case 2 before use case 1” idea below.

    FireRunDaskCoordinator.py — local-dev’s changes braid three use cases into one rewrite of Run: - Run_local is deleted, folded into a single Run that computes use_s3 = settings.READ_LOCATION == "s3" and guards every S3 upload (job_fire_forward gains a use_s3 arg; job_preprocess_region/_region_t guard on READ_LOCATION). (use case 2) - Run’s default ted no longer uses UTC ctime.hour >= 18; it calls get_reg_shp(region) + get_current_timestep(reg_shp) → region-local most-recent timestep. (use case 1 timezone) - CLI gains --reg_shp (if args.reg_shp: Run([regnm, reg_shp], ...)) + Africa/SE_Asia geojson usage examples. (use case 1 shapefile) - job_data_update_checker gains force: bool = True: when ted is within 48h of now, re-downloads & re-processes the last 3 days (rolling NRT backfill window), and handles the case where local ted is after the current UTC day (t2dt(ted) > t2dt(dt2t(ctime))) by mocking the input filepath. Downloads are now sequential (direct update_FIRMS calls, not client.submit) to avoid hammering the FIRMS API. This absorbs the old job_nrt_current_day_updates forced-preprocess logic. (use case 1 timezone + NRT robustness)

    preprocess.py — same braid: - preprocess_input_file now uses aprox_local_datetime(datetime, Lon) (use case 1 timezone) and tolerates missing/None input files with a warning instead of erroring (NRT robustness); adds NOAA21 to the Literal. - New preprocess_NRT_file(t, sat) (timestep-based prev/next via t_nb). - preprocess_daily_file now prefers SP over NRT per-sat and special-cases NOAA21 (no SP) (NRT robustness). - ⚠️ conus-dps’s backfill_inputs_from_FIRMS_bulk_dl is absent from local-dev (it postdates the branch). A port must keep conus-dps’s version — don’t let a wholesale file copy delete it.

    Conclusion: the Run/Run_local unification (use case 2) cannot be merged without get_current_timestep + get_reg_shp (use case 1 timezone/shapefile). These two files deliver UC1 + the coordinator slice of UC2 + NRT robustness as a single inseparable change. Merge them together, after the upstream dependencies (FireTime timezone fns, EPSG_CODE projection, FireObj fid change) are in place.

    🐛 Bug to fix on merge: local-dev Run def has a stray line-continuation: def Run(...):\ (backslash after the colon). Drop it. Also logger.info(settings.model_dump()) was commented out — restore if you want startup config logging.

    Suggested approach (revised after deep-dive)

    Sequence by dependency, not by use case — the global-FEDS dependencies must land before the coordinator can be ported:

    1. Use case 3 (archive) — nearly done; finish the residual coordinator delta + add register-and-run-archive.ipynb. Low risk, independent.
    2. Standalone parts of use case 2 — docs/run_local.md, 20_Download_VIIRS_SP_SFTP.ipynb, test-output cleanup. Pure adds; safe now. (But the Run/Run_local unification is NOT here — see step 4.)
    3. Use case 1 foundations — land the upstream pieces first, ideally as reviewable sub-PRs: (a) FireObj fireID no-reset (check_fid_len replacing newyear_reset, universal), (b) EPSG_CODE multi-CRS/projection, (c) FireTime timezone fns (aprox_local_datetime, get_current_timestep) + FireIO.get_reg_shp plumbing.
    4. The entangled core — port FireRunDaskCoordinator.py + preprocess.py together (delivers --reg_shp CLI, region-local ted, use_s3 unification, NRT force/backfill, SP-preference), preserving conus-dps’s backfill_inputs_from_FIRMS_bulk_dl. Then add 16_Global_FEDS_Manual_Run.ipynb. This single step completes both global FEDS and the local-run unification.

    Open questions to resolve before starting

    • fireID reset: confirm the desired end state — conus-dps resets on new year; local-dev disables reset “but checks length.” Is the no-reset behavior intended for all runs (CONUS NRT included) or only global/archive? This changes whether it’s a clean swap or needs a flag.
    • Run/Run_local unification: verify local-dev’s unified Run is compatible with conus-dps’s current coordinator (which evolved independently) before porting.
    • reg_shp plumbing: confirm whether conus-dps’s partial get_reg_shp is the same shape as local-dev’s or a divergent stub.

    Confidence note: ✅/❌ statuses are from symbol/argparse probes + diff sizes, not a full line read of FireRunDaskCoordinator.py, preprocess.py, FireTime.py, FireObj.py. Treat the use-case groupings and the “missing” calls as solid; treat the 🟡 “partial” items as needing a tip-to-tip diff to scope exactly which hunks remain.
